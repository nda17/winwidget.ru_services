# Автообновление CRM и общий колокольчик

Открытые списки и карточки заявок, сделок, задач, контактов и чата поддержки
обновляются по авторизованным HTTP-запросам после серверного сигнала SSE.
Колокольчик объединяет новые заявки, ответы оператора поддержки и существующие
уведомления о назначениях и сроках задач. Каждый раздел имеет серверную
пагинацию, фильтр непрочитанных и собственную проверку прав.

| Сервис    | Поток SSE                                        | Данные уведомлений                      |
| --------- | ------------------------------------------------ | --------------------------------------- |
| Intake    | `GET /api/v1/crm/intake/events?workspaceId=…`    | `GET /api/v1/crm/intake/notifications`  |
| Sales     | `GET /api/v1/crm/sales/events?workspaceId=…`     | Существующий контракт уведомлений задач |
| Customers | `GET /api/v1/crm/customers/events?workspaceId=…` | —                                       |
| Support   | `GET /api/v1/support/events`                     | `GET /api/v1/support/notifications`     |

Каждый API слушает только собственную PostgreSQL через одно соединение LISTEN.
Триггеры отправляют scope-only NOTIFY после commit, в том числе для записей
фоновых процессов. Это недолговечный сигнал перечитать данные, а не бизнес-команда
или подтверждение доставки. После первого подключения и reconnect клиент всегда
перечитывает текущий HTTP-снимок; при недоступном потоке сохраняется резервное
обновление. Токен передаётся заголовком Authorization через существующий session
lease, без токенов в URL. Каждые 10 секунд сервер проверяет доступ и отправляет
heartbeat/clock; соединение ограничено пятью минутами и автоматически заменяется.
Clock обновляет сроки задач, наступление которых не требует новой записи в БД.

Для каждой новой записи Inbox транзакционно создаётся одно уведомление. Исторические
заявки не заполняют колокольчик задним числом. Доступ к уведомлению совпадает с
`intake:read` и ALL/TEAM/OWN scope самой заявки. Прочтение хранится отдельно для
каждого пользователя; `PUT /api/v1/crm/intake/notifications/:id/read` принимает
`schemaVersion: 1`, `workspaceId`, `read`. Личные отметки доступны и в READ_ONLY.
Ответы поддержки используют существующую историю и монотонный through-sequence
прочтения; сообщения других авторов недоступны. Отметка ответа прочитанным
согласована с чатом. Контракты и точная membership-привязка уведомлений задач
сохранены; ограничение прежних путей создания задач описано в backlog.

Обновление карточки не сбрасывает локальный черновик клиента. При новой серверной
версии показывается конфликт; переход к ней требует явного обновления формы.
Новые классы событий подключаются через владельца данных и его права. Добавление
произвольного события в PostgreSQL само по себе не создаёт новый вид колокольчика.
